# トークン見積もり:テストケース(12区分 × 3パターン = 36)

見積もりの式の係数を決めるための、最初のテストです。12区分(A・B・C・D・E・F・G・H・I・J・K・L・M・N・O を、G・H、J・K、M・N でまとめて12行)を、3パターンずつ、全部で **36ケース** 行います。足りなければ、必要になった区分のケースを、あとから追加します。**M・N(まとめ日記)とO(サーバー側のチェック)は、機能を作ったあとに試します**(表の「実装後」)。

## 全体の流れ

1. **実機テスト(今回)**:あなたが、A〜L(30ケース)を実機で試し、消費トークンをチャットで伝える。私が、この表に記入する。
2. **実装**:実測から、見積もり式の係数を決める。そのあと、サーバー側のチェック、写真・期間の制限をなくす対応、月まとめ、年まとめを実装する。
3. **残りのテスト**:実装後に、M・NとOの6ケースを試し、式を微調整する。

テストを始める前に、`ai_chat_lambda.py` の最新版(モデルの順番を変えたもの)が、Lambdaにデプロイされているか確認する。

## 記録のしかた

1. 作成画面の「消費トークンの目安」を控える。
2. 生成したら、CloudWatchの「AIのチャット」で、時刻が合う行を探す。
   `{"provider": "Gemini", "model": "…", "prompt": …, "output": …, "thoughts": …, "total": …, "seconds": …}`
3. 下の表に書く。失敗したときは、`Gemini` の行と、AppLogの行を控える。
4. 全部、または区分ごとにまとめて、チャットに貼る。係数は、私が計算します。

## 注意

- 無料の枠(月3,000)は、すぐなくなります。写真つきの1回で、約1,600です。枠が尽きたら、アプリを入れ直すか、アカウント紐づけでトークン残高を足してください。
- J・Kは、枠の残りを、わざと少なくする必要があります。AとBなど、先に枠を使うテストを終えてから、行うのがやりやすいです。
- 同じ日・同じ写真セットを使い、変えるのは、ケースで決めた部分だけにしてください。
- アプリを再インストールして、行動履歴がなくなった。**履歴を使うケース(B、GH、I3)は、履歴がたまったあと、最後に行う**。それまでの順番は、A → C → D → E → F → I1・I2 → JK → L。
