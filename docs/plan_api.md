# プランと使用量のAPI(アプリ側が期待する形)

アプリは、ここに書いた形で通信する。サーバーが未対応でも、アプリは動く
(使用量が表示されないだけで、日記は生成できる)。

## 共通

- すべてのリクエストに、端末を識別する匿名のIDを付ける。
  - ヘッダー `X-Client-Id`: 32桁の英数字(アプリのインストールごとに1つ。個人情報は含まない)
- 使用量は **トークン数** で数え、**月単位** で集計する。
  - 上限に達したら、翌月のリセットまでAIを使えない。
  - 月の区切りは、サーバーが決める(`resetsAt` でアプリに伝える)。
- 上限の値は、サーバーだけが持つ。アプリは値を決め打ちせず、サーバーが返した値を表示する。

## 使用量とプランの形(`usage`)

応答のJSONに、次の2つを入れる。

```json
{
  "plan": "free",
  "usage": {
    "usedTokens": 1200,
    "limitTokens": 50000,
    "resetsAt": "2026-11-01T00:00:00+09:00"
  }
}
```

| 項目 | 説明 |
|---|---|
| `plan` | サーバーが判定したプラン。`free` または `paid`。アプリのプランはこの値に合わせる |
| `usage.usedTokens` | 今月に使ったトークン数(今回の呼び出しを含む) |
| `usage.limitTokens` | 今月に使えるトークン数の上限(プランで変わる) |
| `usage.resetsAt` | 使用量がリセットされる日時(ISO 8601) |

## `POST /ai/chat`(既存の変更)

- 成功(200): 既存の `answer` に加えて、上の `plan` と `usage` を返す。
  `usage` は、この呼び出しで消費したトークンを加えた値にする。
- **上限に達している場合(429)**: AIを呼び出さずに、次の本文を返す。

```json
{
  "error": "usage_limit_exceeded",
  "plan": "free",
  "usage": { "usedTokens": 50000, "limitTokens": 50000, "resetsAt": "2026-11-01T00:00:00+09:00" }
}
```

  本文が空でも、アプリは「上限に達した」として扱う。

## `GET /plan/usage`(新規)

設定画面やプラン画面で、今月の使用量を表示するために呼ぶ。

- 成功(200): 上の `plan` と `usage` を返す。
- 未対応(404など)の場合、アプリは使用量を表示しない。

## 有料プランの判定(アプリ内課金を入れるときに追加)

アプリ内課金(Google Play・App Store)を入れるときに、サーバーでの購読の確認を追加する。
詳細は、課金の実装時に決める。想定は次のとおり。

- アプリが購入後に、ストアのレシート(購入トークン)をサーバーに送る。
- サーバーが、Google Play Developer API / App Store Server API で購読を確認し、
  `X-Client-Id` と結びつけて、`plan` を `paid` にする。
- 解約や期限切れは、サーバーがストアに問い合わせて反映する(アプリは `plan` を見るだけ)。
